# Gitコマンド一覧

このページでは、仕様駆動開発の練習でよく使用するGitコマンドをまとめています。

## GitコマンドとVS Codeの操作対応表

下記の表は、よく使うGitコマンドごとに「コマンドの説明」「VS Codeでの操作方法」「チャットパネルでの指示例」をまとめたものです。VS Code標準のGit機能で行う操作と、コマンドの厳密な指定が必要なため統合ターミナルで行う操作を示します。

### このページの前提

- Windows版のVS Codeで、Gitをインストール済みの環境を想定しています。「ファイル」→「フォルダーを開く」で対象のリポジトリを開いてください。通常のGit操作に管理者権限は不要です。
- ソース管理は `Ctrl+Shift+G`、コマンドパレットは `Ctrl+Shift+P` で開きます。ターミナルは「ターミナル」→「新しいターミナル」から開き、リポジトリのフォルダーでコマンドを実行します。以下のGitコマンドはPowerShellでも使えます。
- UIの名称は英語表記を併記しています。日本語表示では「Source Control」は「ソース管理」、「Changes」は「変更」、「Staged Changes」は「ステージされている変更」です。表示名やメニュー配置はバージョン・設定で異なるため、見つからない操作はコマンドパレットで `Git:` を検索してください。
- **チャットでの指示例は任意の補助機能です。** 利用するAIサービス（例：GitHub Copilot）の設定・サインインを済ませ、ターミナルコマンドを実行できるエージェントを選択した場合を想定しています。「Chat: Open Chat」から開き、対象リポジトリやファイルを指定してください。説明のみを返すチャットではコマンドは実行されません。実行権限の確認が出た場合は内容を確認し、実行後はソース管理や `git status` で結果を確認します。GitのGUI操作自体にはAI機能は不要です。

| Gitコマンド | 説明 | VS Codeでの操作方法 | チャットパネルでの指示例（上記の前提あり） |
|------------|------|-------------------|---------------------|
| `git status` | 変更されたファイルの一覧を確認 | Source Controlパネル（Ctrl+Shift+G）を開く | 「git statusを実行して」または「変更されたファイルの状態を確認して」 |
| `git add .` | すべての変更をステージング | Source Controlパネルの「Changes」セクションの上にある「+」ボタン | 「すべての変更をステージングして」 |
| `git add ファイル名` | 特定のファイルをステージング | ファイルの横にある「+」ボタン | 「README.mdをステージングして」 |
| `git commit -m "メッセージ"` | コミットを実行 | 対象をステージし、メッセージを入力して「Commit」ボタン（入力欄でCtrl+Enter） | 「コミットして」または「変更をコミットして」 |
| `git push` | リモートリポジトリにプッシュ | コマンドパレットで「Git: Push」。初回で追跡先がない場合は「Publish Branch」 | 「プッシュして」 |
| `git pull` | リモートリポジトリから最新の変更を取得 | コマンドパレットで「Git: Pull」 | 「最新の変更を取得して」または「プルして」 |
| `git switch ブランチ名` | ブランチを切り替え（旧: `git checkout`） | ステータスバーのブランチ名をクリックして切り替え | 「ブランチ名に切り替えて（例：mainブランチに切り替えて）」 |
| `git switch -c ブランチ名` | 新しいブランチを作成して切り替え（旧: `git checkout -b`） | ステータスバーのブランチ名をクリック→「Create new branch...」 | 「ブランチ名を作成して切り替えて（例：featureブランチを作成して切り替えて）」 |
| `git diff` | 変更内容をdiff形式で表示 | ソース管理の「Changes」のファイルをクリック。ステージ済みの差分は「Staged Changes」から開く | 「変更の差分を表示して」または「git diffを実行して」 |
| `git reset ファイル名` | ステージングを取り消し | 「Staged Changes」セクションのファイルの横の「-」ボタン | 「README.mdのステージングを取り消して」 |
| `git restore ファイル名` | ファイルの変更を取り消し（**⚠️ 注意：変更が失われます**） | ファイルを右クリック→「Discard Changes」 | 「README.mdの変更を取り消して」 |
| `git branch` | ブランチの一覧を確認 | ステータスバーのブランチ名をクリックして一覧を表示（確認のみならEscで閉じる）。ローカルだけの一覧は統合ターミナルで実行 | 「ブランチの一覧を表示して」または「git branchを実行して」 |
| `git branch ブランチ名` | 新しいブランチを作成 | 統合ターミナルで実行。「Git: Create Branch」は作成後に切り替えも行う | 「ブランチ名を作成して（例：featureブランチを作成して）」 |
| `git branch -d ブランチ名` | ブランチを削除 | 別ブランチに切り替え、コマンドパレットで「Git: Delete Branch」 | 「ブランチ名を削除して（例：featureブランチを削除して）」 |
| `git branch -D ブランチ名` | ブランチを強制削除（**⚠️ 危険：マージされていない変更も削除されます**） | 統合ターミナルで実行し、強制削除する対象を明示する | 「ブランチ名を強制削除して（例：featureブランチを強制削除して）」 |
| `git log` | コミット履歴を確認 | ソース管理の「Source Control Graph」で履歴を確認。同じ詳細出力は統合ターミナルで実行 | 「コミット履歴を表示して」または「git logを実行して」 |
| `git log --oneline` | コミット履歴を簡潔に表示 | 「Source Control Graph」でコミット一覧を確認。1行形式のテキスト出力は統合ターミナルで実行 | 「コミット履歴を簡潔に表示して」 |
| `git log --graph --oneline --all` | コミット履歴をグラフ形式で表示 | 「Source Control Graph」で履歴とブランチの関係を表示。--allを含む同じ出力は統合ターミナルで実行 | 「コミット履歴をグラフ形式で表示して」 |
| `git show コミットハッシュ` | 特定のコミットの内容を確認 | 「Source Control Graph」でコミットを選び、変更ファイルをクリックして差分を開く | 「最新のコミットの内容を表示して」または「このコミットの内容を表示して」 |
| `git commit --amend` | 最後のコミットを修正（**⚠️ 注意：既にプッシュした場合は危険**） | 修正内容をステージし、コマンドパレットで「Git: Commit Staged (Amend)」 | 「最後のコミットを修正して」または「最後のコミットメッセージを修正して」 |
| `git merge ブランチ名` | ブランチをマージ | 取り込み先に切り替え、「Git: Merge Branch」で取り込むブランチを選択 | 「ブランチ名をマージして（例：featureブランチをマージして）」 |
| `git rebase ブランチ名` | ブランチをリベース（**⚠️ 注意：既にプッシュしたコミットに対しては危険**） | 統合ターミナルで実行し、現在のブランチを載せ替える基点を明示する | 「ブランチ名をリベースして（例：featureブランチをリベースして）」 |
| `git reset --soft HEAD~1` | 最後のコミットを取り消す（変更は保持）（**⚠️ 注意：既にプッシュした場合は危険**） | ソース管理の「...」→「Commit」→「Undo Last Commit」。厳密にコマンドを指定するなら統合ターミナルで実行 | 「最後のコミットを取り消して（変更は保持）」 |
| `git remote -v` | リモートリポジトリの情報を確認 | fetch用・push用URLを正確に確認するには統合ターミナルで実行 | 「リモートリポジトリの情報を表示して」または「git remote -vを実行して」 |
| `git remote add origin URL` | リモートリポジトリを追加 | コマンドパレットで「Git: Add Remote」。URLとリモート名originを入力 | 「リモートリポジトリを追加して（URLは指定が必要）」 |
| `git fetch` | リモートリポジトリの情報を取得（マージはしない） | コマンドパレットで「Git: Fetch」 | 「リモートリポジトリの情報を取得して」または「git fetchを実行して」 |

**補足**: GUIはコマンドと同じ目的を達成する操作を示しており、出力形式や対象範囲まで一致するとは限りません。`git add .` はカレントディレクトリ以下が対象なので、全変更を追加する例ではリポジトリのルートで実行してください。「Sync Changes（変更の同期）」はPullの後にPushも実行する操作です。取得だけなら「Git: Pull」、送信だけなら「Git: Push」を選択します。

## 基本的な操作（詳細説明）

### リポジトリの状態を確認する

```bash
git status
```

現在のブランチ、変更されたファイル、ステージングエリア（コミット対象の変更を一時的に保存する場所）の状態を確認できます。

**VS Codeでの操作方法**: 左側のサイドバーから「Source Control」アイコン（Ctrl+Shift+G）をクリックすると、変更されたファイルの一覧が表示されます。ステータスバー（画面下部）に現在のブランチ名も表示されます。

**チャットパネルでの指示**: 「git statusを実行して」または「変更されたファイルの状態を確認して」

### 変更をステージングエリア（コミット対象に追加）に追加する

```bash
# Tip: コミットするべきでないファイルが含まれていないか、事前に git status で確認しましょう
git status

# すべての変更を追加
git add .

# 特定のファイルを追加
git add README.md

# 特定のディレクトリを追加
git add docs/
```

**VS Codeでの操作方法**: Source Controlパネルで、変更されたファイルの横にある「+」ボタンをクリックすると、そのファイルがステージングされます。「Changes」セクションの上にある「+」ボタンをクリックすると、すべての変更を一度にステージングできます。

**チャットパネルでの指示**:

- すべての変更をステージングする場合：「すべての変更をステージングして」
- 特定のファイルをステージングする場合：「README.mdをステージングして」

### コミットする

```bash
git commit -m "コミットメッセージ"
```

変更をローカルリポジトリに記録します。コミットメッセージは、何を変更したかが分かるように簡潔に記述してください。

**VS Codeでの操作方法**: ソース管理で対象ファイルをステージし、「Staged Changes」の差分を確認します。メッセージ欄に入力し、「Commit（コミット）」ボタンを押すか、入力欄でCtrl+Enterを押します。自動ステージングは設定によって挙動が異なるため、この手順では先に対象をステージします。

**チャットパネルでの指示**: 「コミットして」または「変更をコミットして」

### リモートリポジトリにプッシュする

```bash
git push
```

ローカルリポジトリの変更をリモートリポジトリに送信します。

**VS Codeでの操作方法**: コマンドパレットで「Git: Push」を実行するか、ソース管理の「...」メニューから「Push」を選択します。追跡先のない新しいブランチは「Publish Branch」で公開します。「Sync Changes」はPullも行うため、Pushだけを行いたい場合は使いません。

**チャットパネルでの指示**: 「プッシュして」

### リモートリポジトリから最新の変更を取得する

```bash
git pull
```

リモートリポジトリの最新の変更をローカルリポジトリに取り込みます。

**VS Codeでの操作方法**: コマンドパレットで「Git: Pull」を実行するか、ソース管理の「...」メニューから「Pull」を選択します。同期アイコンの「Sync Changes」はPullの後にPushも行います。

**チャットパネルでの指示**: 「最新の変更を取得して」または「プルして」

## リポジトリの操作

### リモートリポジトリを作成する

リモートリポジトリの作成は、以下の3つの方法があります。

#### 方法1: GitHubのWeb画面から作成（推奨）

1. GitHubにログインし、右上の「+」アイコンから「New repository」を選択
2. リポジトリ名、公開設定（Public/Private）を入力して「Create repository」をクリック
3. 作成後、表示される指示に従ってローカルリポジトリと接続

**詳しい手順**: [GitHub公式ドキュメント](https://docs.github.com/ja/repositories/creating-and-managing-repositories/creating-a-new-repository)を参照してください。

#### 方法2: GitHub CLI（gh）を使って作成

GitHub CLIをインストール済みであれば、以下のコマンドで作成できます：

```bash
gh repo create リポジトリ名 --public --source=. --remote=origin --push
```

**コマンドの説明**:

- `--public`: 公開リポジトリとして作成（`--private`で非公開リポジトリ）
- `--source=.`: 現在のディレクトリをソースとして使用
- `--remote=origin`: リモート名を`origin`として設定
- `--push`: 作成後に自動的にプッシュ

**チャットパネルでの指示**: 「リモートリポジトリを作成して」または「gh repo createコマンドでGitHubにリポジトリを作成して」

**注意**: GitHub CLIのインストール方法については、第4章4.3節「GitHub CLI（gh）をインストール・設定する」を参照してください。

#### 方法3: VS CodeからGitHubに公開する

リモートに接続していないローカルリポジトリを開き、ソース管理の「Publish to GitHub」を選択します。GitHubにサインインし、リポジトリ名・公開範囲（Public/Private）を選択すると、GitHubでのリポジトリ作成、リモートの追加、コミットのプッシュが行われます。「Publish Branch」は既存のリモートにブランチを公開する操作です。

### リモートリポジトリをクローンする

```bash
git clone https://github.com/ユーザー名/リポジトリ名.git
```

リモートリポジトリをローカル環境にコピーします。

**VS Codeでの操作方法**: コマンドパレットで「Git: Clone」を実行し、URLとローカルの保存先を指定して、完了後にフォルダーを開きます。SSH認証を設定済みなら `git@github.com:ユーザー名/リポジトリ名.git` も指定できます。

### GitHubリポジトリをアーカイブする

**注意**: この操作はGitコマンドではなく、GitHubのWebインターフェースでの操作です。

GitHubでは、リポジトリをアーカイブすることができます。アーカイブされたリポジトリは読み取り専用になり、新しいコミットやIssue、Pull Requestの作成はできなくなりますが、既存の内容はすべて保持され、いつでも参照可能です。

**GitHubでの操作方法**:
1. リポジトリの「Settings」タブを開く
2. ページ下部の「Danger Zone」セクションを開く
3. 「Archive this repository」をクリック
4. 確認ダイアログでリポジトリ名を入力してアーカイブを実行

**用途**: 活用頻度が低いレガシー文書を管理するリポジトリを「参照用」として保管する際に有効です。

**注意**: アーカイブされたリポジトリは、必要に応じてアーカイブを解除することもできます。

### リモートリポジトリの情報を確認する

```bash
git remote -v
```

設定されているリモートリポジトリのURLを確認できます。

**チャットパネルでの指示**: 「リモートリポジトリの情報を表示して」または「git remote -vを実行して」

**VS Codeでの操作方法**: 統合ターミナルで `git remote -v` を実行すると、fetch用とpush用のURLを確認できます。

### リモートリポジトリを追加する

```bash
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
```

新しいリモートリポジトリを追加します。

**チャットパネルでの指示**: 「リモートリポジトリを追加して（URLは指定が必要）」

**VS Codeでの操作方法**: コマンドパレットで「Git: Add Remote」を実行し、URLとリモート名（例：origin）を入力します。

## ブランチの操作

### ブランチの一覧を確認する

```bash
# ローカルブランチの一覧
git branch

# リモートブランチも含めた一覧
git branch -a
```

**チャットパネルでの指示**: 「ブランチの一覧を表示して」または「git branchを実行して」

**VS Codeでの操作方法**: ステータスバーのブランチ名をクリックするとローカル・リモートのブランチ候補を確認できます。切り替えず閉じるにはEscを押します。`git branch` や `git branch -a` と同じ一覧を得るには統合ターミナルで実行します。

### 新しいブランチを作成する

```bash
git branch ブランチ名
```

新しいブランチを作成します（作成後は現在のブランチのままです）。

**チャットパネルでの指示**: 「ブランチ名を作成して（例：featureブランチを作成して）」

**VS Codeでの操作方法**: 作成だけを行い現在のブランチに留まる場合は、統合ターミナルで実行します。「Git: Create Branch」は作成と切り替えを行うため、次の「ブランチを作成して切り替える」を参照してください。

### ブランチを切り替える

```bash
# 推奨
git switch ブランチ名

# 旧コマンド
git checkout ブランチ名
```

**VS Codeでの操作方法**: ステータスバーのブランチ名をクリックするか、コマンドパレットで「Git: Checkout to」を実行し、切り替え先を選択します。

**チャットパネルでの指示**: 「ブランチ名に切り替えて（例：mainブランチに切り替えて）」

### ブランチを作成して切り替える（一度に）

```bash
# 推奨
git switch -c ブランチ名

# 旧コマンド
git checkout -b ブランチ名
```

**VS Codeでの操作方法**: ステータスバーのブランチ名をクリックし、「Create new branch...」を選択して、新しいブランチ名を入力します。

**チャットパネルでの指示**: 「ブランチ名を作成して切り替えて（例：featureブランチを作成して切り替えて）」

### ブランチを削除する

```bash
# ローカルブランチを削除
git branch -d ブランチ名

# 強制削除（マージされていないブランチも削除）
git branch -D ブランチ名
```

**⚠️ 注意**: `git branch -D`は強制削除コマンドです。マージされていない変更も含めてブランチを削除するため、**データが失われる可能性があります**。通常は`git branch -d`を使用し、マージ済みのブランチのみ削除することを推奨します。

**チャットパネルでの指示**: 「ブランチ名を削除して（例：featureブランチを削除して）」。強制削除が必要な場合のみ「ブランチ名を強制削除して（例：featureブランチを強制削除して）」

**VS Codeでの操作方法**: 削除対象とは別のブランチに切り替え、「Git: Delete Branch」で対象を選択します。未マージの場合に強制削除を求められても、通常の削除だけが目的なら中止します。`-D` を明示して強制削除する場合は統合ターミナルで実行します。

### ブランチをマージする

```bash
git merge ブランチ名
```

指定したブランチを現在のブランチにマージします。

**チャットパネルでの指示**: 「ブランチ名をマージして（例：featureブランチをマージして）」

**VS Codeでの操作方法**: 取り込み先のブランチに切り替えてから「Git: Merge Branch」を実行し、取り込むブランチを選びます。

### ブランチをリベースする

```bash
git rebase ブランチ名
```

現在のブランチのコミットを、指定したブランチを基点として載せ替えます。

**⚠️ 注意**: リベースはコミット履歴を書き換える操作です。**既にプッシュしたコミットに対してリベースを実行すると、他の人と履歴がずれて問題が発生する可能性があります**。プッシュ前のローカルブランチでのみ使用することを推奨します。既にプッシュしたブランチをリベースした場合は、`git push --force`が必要になりますが、共有リポジトリでは避けてください。

**チャットパネルでの指示**: 「ブランチ名をリベースして（例：featureブランチをリベースして）」

**VS Codeでの操作方法**: 統合ターミナルで実行します。たとえばfeatureブランチを開いた状態で `git rebase main` を実行すると、featureのコミットをmainの先端に載せ替えます。

### リモートリポジトリの情報を取得する（マージはしない）

```bash
git fetch
```

リモートリポジトリの最新の情報を取得しますが、ローカルブランチにはマージしません。

**チャットパネルでの指示**: 「リモートリポジトリの情報を取得して」または「git fetchを実行して」

**VS Codeでの操作方法**: コマンドパレットで「Git: Fetch」を実行します。取得した履歴はSource Control Graphから確認できます。

## 変更の確認と比較

### 変更内容を確認する

```bash
# ステージング（コミット対象に追加）されていない変更を確認
git diff

# ステージング（コミット対象に追加）された変更を確認
git diff --staged

# 特定のファイルの変更を確認
git diff README.md
```

**VS Codeでの操作方法**: ソース管理の「Changes」からファイルを開くと未ステージの差分、「Staged Changes」から開くとステージ済みの差分を確認できます。追加・削除された行が色分けされ、左右比較またはインライン表示で確認できます。

**チャットパネルでの指示**: 「変更の差分を表示して」または「git diffを実行して」

### コミット履歴を確認する

```bash
# 簡潔な履歴
git log --oneline

# 詳細な履歴
git log

# グラフ形式で表示
git log --graph --oneline --all
```

**チャットパネルでの指示**: 「コミット履歴を表示して」または「git logを実行して」。簡潔に表示する場合は「コミット履歴を簡潔に表示して」。グラフ形式の場合は「コミット履歴をグラフ形式で表示して」

**VS Codeでの操作方法**: ソース管理の「Source Control Graph」を開き、コミットとブランチの関係を確認します。ファイル単位の履歴はエクスプローラーの「Timeline」でも確認できます。上記コマンドの形式・範囲どおりに出力したい場合は統合ターミナルを使います。

### 特定のコミットの内容を確認する

```bash
git show コミットハッシュ
```

**チャットパネルでの指示**: 「最新のコミットの内容を表示して」または「このコミットの内容を表示して」

**VS Codeでの操作方法**: Source Control Graphで対象コミットを選択し、変更ファイルをクリックして差分を開きます。ハッシュを直接指定してテキストで確認する場合は統合ターミナルで `git show` を実行します。

## 変更の取り消し

### ステージング（コミット対象から除外）を取り消す

```bash
# すべてのステージングを取り消す
git reset

# 特定のファイルのステージングを取り消す
git reset README.md
```

**VS Codeでの操作方法**: Source Controlパネルの「Staged Changes」セクションで、ファイルの横にある「-」ボタンをクリックすると、そのファイルのステージング（コミット対象に追加）が取り消されます。

**チャットパネルでの指示**: 「README.mdのステージングを取り消して」

### ファイルの変更を取り消す（注意：変更が失われます）

```bash
git restore ファイル名
```

**チャットパネルでの指示**: 「README.mdの変更を取り消して」

**VS Codeでの操作方法**: Source Controlパネルで変更されたファイルを右クリックし、「Discard Changes」を選択します。確認ダイアログが表示されるので、承認すると変更が取り消されます。

### 最後のコミットを修正する（コミットメッセージを変更）

```bash
git commit --amend -m "新しいコミットメッセージ"
```

**⚠️ 注意**: `git commit --amend`はコミット履歴を書き換える操作です。**既にプッシュしたコミットを修正する場合は、`git push --force`が必要になりますが、他の人と共有しているリポジトリでは避けてください**。共有リポジトリで実行すると、他の人の作業に影響を与える可能性があります。

**チャットパネルでの指示**: 「最後のコミットを修正して」または「最後のコミットメッセージを修正して」

**VS Codeでの操作方法**: メッセージ欄に新しいメッセージを入力し、「Git: Commit Staged (Amend)」を実行します。ステージ済みの変更があると、その内容も直前のコミットに含まれるため、メッセージだけを変える場合はステージ済みの変更がないことを確認します。

### 最後のコミットを取り消す（変更は保持）

```bash
git reset --soft HEAD~1
```

最後のコミットを取り消しますが、変更内容はステージングエリア（コミット対象の変更を一時的に保存する場所）に保持されます。

**⚠️ 注意**: `git reset`はコミット履歴を書き換える操作です。**既にプッシュしたコミットを取り消す場合は、`git push --force`が必要になりますが、他の人と共有しているリポジトリでは避けてください**。共有リポジトリで実行すると、他の人の作業に影響を与える可能性があります。

**チャットパネルでの指示**: 「最後のコミットを取り消して（変更は保持）」

**VS Codeでの操作方法**: ソース管理の「...」→「Commit」→「Undo Last Commit」で直前のコミットを取り消せます。変更は「Staged Changes」に残るので、差分を確認して再コミットできます。コマンドを明示して操作する場合は統合ターミナルで `git reset --soft HEAD~1` を実行します。

```bash
git push
```

## VS CodeでのGit操作（まとめ）

VS Codeでは、Source ControlパネルからGUIでGit操作を行うことができます。多くの操作はコマンドラインを使わずに実行できます：

### 基本的な操作フロー

1. **左側のサイドバー**から「Source Control」アイコン（Ctrl+Shift+G）をクリック
2. 変更されたファイルが「Changes」セクションに表示されます
3. ファイルの横の「+」ボタンでステージング（コミット対象に追加）（または「Changes」セクションの上の「+」で一括ステージング）
4. 上部のテキストボックスに対象をステージし、メッセージを入力して「Commit」ボタン（入力欄でCtrl+Enter）でコミット
5. 「...」メニューから「Push」を選択してプッシュ、取得と送信の両方を行う場合は「Sync Changes」を選択（Pullの後にPush）

### その他の便利な機能

- **変更の確認**: ファイルをクリックすると、diffが表示されます
- **ブランチの切り替え**: ステータスバーのブランチ名をクリック
- **履歴の確認**: ソース管理の「Source Control Graph」でコミットを選び、変更ファイルの差分を開く
- **フェッチ・プル・プッシュ**: コマンドパレットの「Git: Fetch」「Git: Pull」「Git: Push」を使い分ける
- **変更の取り消し**: ファイルを右クリックして「Discard Changes」を選択

## トラブルシューティング

### コンフリクトが発生した場合

**VS Codeでの操作方法**: ソース管理の競合ファイルを開き、エディター内の変更採用ボタン、または「Resolve in Merge Editor」でマージエディターを使って結果を編集します。解決後に保存・ステージし、マージ中ならコミットします。リベース中なら統合ターミナルで `git rebase --continue` を実行します。以下はマージ時のコマンド例です。

```bash
# 1. コンフリクトの状態を確認（"both modified" と表示されるファイルがある）
git status

# 2. ファイルを開き、コンフリクトマーカー（<<<<<<<, =======, >>>>>>>）を探して修正する
# 例：
# <<<<<<< HEAD
# 現在の変更
# =======
# 相手の変更
# >>>>>>> feature/xxx
#
# ↑これらを削除し、正しいコードだけを残す

# 3. 修正したらステージング
git add .

# 4. マージを完了
git commit -m "コンフリクトを解決"
```

### 間違えてコミットした場合

```bash
# 最後のコミットを取り消す（変更は保持）
git reset --soft HEAD~1

# 変更を確認してから再度コミット
git status
git commit -m "正しいコミットメッセージ"
```

### リモートリポジトリと同期が取れていない場合

```bash
# リモートの状態を確認
git fetch

# リモートとローカルの差分を確認
git log HEAD..origin/main

# 必要に応じてプル
git pull
```
